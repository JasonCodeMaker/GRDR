Fix design — P1 (control)

P1 — Shared token_idx Across Pseudo Siblings

Forces all pseudo captions of a video to inherit the real caption's token_idx, removing per-row routing variance under multi-caption supervision. This is the cheap control fix: it severs the "per-video num_texts > 1" conjunct of the failure trigger without touching the foundation cause (select-one-slot CE). Predicted to underperform P3 — this doc explains why we still run it (H3 falsification of "P1 alone is enough"). Implemented in cell F3.

Docs index P3 — all-slot CE View diversification Plan / Experiments

1 Challenge

code anchors: utils/data_utils.py:386-422 · data/video_dataset.py:313-318

Under multi-caption-per-video (pseudo on Panda, native on MSR-VTT), the per-video text k-means at assign_tokens_per_video clusters all captions of one video into k = min(num_latent_tokens, num_texts) groups and assigns each caption a token_idx. For one video with 5 captions (1 real + 4 pseudo) and NLT=4: k=4 ⇒ the 5 captions split across 4 slots ⇒ the same video's 5 rows can pick 4 different slots in the train_step.

  CURRENT (with pseudo + NLT=4)         AFTER P1 (pseudo siblings share real-caption slot)
  ─────────────────────────────         ─────────────────────────────────────────────────
   video_42 captions:                    video_42 captions:
   c1 real    → token_idx = 0            c1 real    → token_idx = 0   (real k-means: k=1)
   c2 pseudo  → token_idx = 2            c2 pseudo  → token_idx = 0   (inherit from c1)
   c3 pseudo  → token_idx = 0            c3 pseudo  → token_idx = 0
   c4 pseudo  → token_idx = 1            c4 pseudo  → token_idx = 0
   c5 pseudo  → token_idx = 3            c5 pseudo  → token_idx = 0
   ⇒ same video, 4 slots, 4 codes       ⇒ same video, 1 slot, 1 code, 5× reinforced

2 Motivation

P1 is a control variant, not a primary fix. Two reasons it's worth the compute slot:

#reasonwhat it gives us
1 Falsifies the alternate hypothesis — "the per-row token_idx variance was actually the dominant cause; P3 wasn't necessary" If F3 (P1 alone) ≈ F2 (P3 + view diversification), then the loss-side redesign was overkill. If F3 < F2 by a clear margin (predicted ~5+ pp on CanHit@100), H3 holds and the necessity of flipping select(token_idx) off is empirically established. Without F3, a reviewer can plausibly demand "did you actually need the loss-side fix or would the cheap data-side fix have worked?"
2 Quantifies the degenerate baseline — how good is "NLT=4 with 3 dormant MLPs" really? F3 effectively trains as NLT=1 with the multi-view encoder still in the forward pass but only slot 0 receiving CE. If F3 ≈ B1 (matches the NLT=1 baseline), it confirms the §2.5 truth-table row 3 prediction that 3 dormant MLPs add nothing.
structural prediction (from diagnostic §2.5) On Panda with only P1 applied, the per-video k-means short-circuits to k = min(N, num_texts) where num_texts = 1 (only the real caption is clustered). That returns labels = zeros; the pseudo siblings inherit token_idx = 0. So all 5 rows of every video go to slot 0. The encoder still has 4 MLPs; slots 1, 2, 3 receive no CE gradient — only reconstruction and rq. This is exactly the diagnostic's row-3 configuration ("NLT=4 + no-pseudo behavior") and the archived MSR-VTT experiment (E2.4F.1) under matched conditions concluded "no promotable method".

4.1 utils/data_utils.py::assign_tokens_per_video — cluster real-only, propagate to pseudo siblings

Current behavior clusters all captions of a video (real + pseudo) jointly. P1 short-circuits this to "cluster only real captions; pseudo siblings inherit". On Panda where each video has exactly 1 real caption, this collapses to "every row of every video gets token_idx = 0".

# utils/data_utils.py — assign_tokens_per_video (broken-vs-fixed branch)
def assign_tokens_per_video(video_features, text_features, num_latent_tokens,
                             logger=None, shared_token_idx_per_video=False,
                             real_caption_keys=None):
    """
    Returns: text_groups = {text_key: token_idx}

    If shared_token_idx_per_video=True (P1 mode):
      - Cluster ONLY the real-caption text embeddings for each video.
      - All pseudo siblings of that video inherit the real-caption label.
      - On Panda (1 real / video), this collapses to token_idx = 0 for every row.

    real_caption_keys: optional set of text_keys identifying real captions.
      If None and shared_token_idx_per_video=True, we fall back to treating
      the FIRST text_key per video as the real one (matches dataset build order).
    """
    text_groups = {}
    video_text_map = defaultdict(list)
    for text_key in text_features.keys():
        video_id = '_'.join(text_key.split('_')[:-1])
        if video_id in video_features:
            video_text_map[video_id].append(text_key)

    for video_id, text_keys in tqdm(video_text_map.items(), desc="K-means"):
        if shared_token_idx_per_video:                    # ─── NEW (P1) ───
            # Identify real captions; cluster only those
            if real_caption_keys is not None:
                real_keys = [k for k in text_keys if k in real_caption_keys]
            else:
                real_keys = [text_keys[0]]                # fall back: first key per video

            if len(real_keys) == 0:
                # All-pseudo video (should not happen in practice); treat as token 0
                for tk in text_keys: text_groups[tk] = 0
                continue

            real_embs = np.array([text_features[k] for k in real_keys])
            k = min(num_latent_tokens, len(real_keys))
            if k == 1:
                shared_label = 0                          # short-circuit (Panda case)
            else:                                         # multi-real datasets (MSR-VTT-like)
                kmeans = KMeans(n_clusters=k, random_state=42, n_init=3,
                                max_iter=20, algorithm='lloyd')
                real_labels = kmeans.fit_predict(real_embs)
                # Propagation rule: pseudo inherits its NEAREST real caption's label.
                # For each pseudo key, find argmin distance to a real_emb, take its label.
                for tk in text_keys:
                    if tk in real_caption_keys:
                        rk_idx = real_keys.index(tk)
                        text_groups[tk] = int(real_labels[rk_idx])
                    else:
                        pseudo_emb = text_features[tk]
                        dists = np.linalg.norm(real_embs - pseudo_emb, axis=1)
                        text_groups[tk] = int(real_labels[dists.argmin()])
                continue

            # k==1 short-circuit: all keys (real + pseudo) get shared_label
            for tk in text_keys:
                text_groups[tk] = shared_label
        else:                                              # ─── OLD (default; B1, B2, B3, F2) ───
            text_embs = np.array([text_features[tk] for tk in text_keys])
            num_texts = len(text_keys)
            k = min(num_latent_tokens, num_texts)
            if k == 1:
                labels = np.zeros(num_texts, dtype=int)
            else:
                kmeans = KMeans(n_clusters=k, random_state=42, n_init=3,
                                max_iter=20, algorithm='lloyd')
                labels = kmeans.fit_predict(text_embs)
            for tk, lab in zip(text_keys, labels):
                text_groups[tk] = int(lab)

    return text_groups

4.2 Identifying real vs pseudo captions

Pseudo captions on Panda live in data/panda/video_retreival_caption/panda_ret_train_addition.json (loaded at video_dataset.py:217-229). Real captions come from panda_ret_train.json. The simplest discriminator: the order of annotations.extend(pseudo_annotations) means the first N entries per video are real (N=1 on Panda). The dataset builder at video_dataset.py:256-275 indexes captions by counter: video_id = f"{raw_video_id}_{count}". So text_key ending in _0 is the real caption (the first counter for that video).

# In utils/data_utils.py wrapper or run.py:
real_caption_keys = {
    tk for tk in text_features.keys()
    if tk.endswith('_0')                           # counter==0 is real on Panda
}
# Threaded into assign_tokens_per_video as real_caption_keys=real_caption_keys
caveat — key-suffix discriminator is Panda-specific The _0 == real rule holds because Panda has exactly 1 real caption per video and pseudo always appends after. For multi-real-caption datasets (MSR-VTT-like), need a different discriminator — e.g. a separate real_caption_keys file built by the subset-builder at P0. This package targets Panda 500K so the simple rule is fine; extension to MSR-VTT is out of scope.

4.4 Cache invalidation

The per-video k-means result is cached at kmeans_cache_path(dataset_name, 'train', num_latent_tokens, cache_dir, use_pseudo_queries). Adding shared_token_idx_per_video as a new dimension changes the cache key. Add it to the cache-path computation so F3 doesn't re-use B3's cached labels.

# utils/data_utils.py — cache key wrapper
def kmeans_cache_path(dataset, split, n, cache_dir, use_pseudo, shared_per_video=False):
    suffix = '_shared_tokidx' if shared_per_video else ''
    return f'{cache_dir}/{dataset}_{split}_nlt{n}{"_pseudo" if use_pseudo else ""}{suffix}.json'
