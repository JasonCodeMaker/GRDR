Fix design — View diversification (F2)

View Diversification — making the 4 slots learn semantically distinct views

P3 alone supervises all N slots but does not guarantee they learn different things; the optimizer can collapse all N MLPs to the same function. This fix adds three training-signal mechanisms without partitioning the codebook: (a) caption-conditioned soft-weighted CE via token_idx, (b) inter-slot orthogonality regularizer, (c) per-slot k-means init at step 0 only. The 4096 codebook stays shared — two videos' "action view" should still argmin to the same centroid (correct semantic aggregation, not artificial separation). Implemented in cell F2.

1 Challenge

After P3 (all-slot CE) is in place, every slot of the multi-view encoder receives retrieval-aware gradient. But P3 by itself does not prevent the 4 MLPs from converging to identical functions. The optimizer's simplest solution under N independent CE losses against the same codebook is:

  P3 alone — risk of view collapse
  ────────────────────────────────
   pooled_features ─► MLP_0 ─┐
                    ─► MLP_1 ─┼─► all 4 MLPs converge to identity-like fn → same feature vector v
                    ─► MLP_2 ─┤
                    ─► MLP_3 ─┘   → all 4 slots argmin to same centroid → 4 identical codes
                                  → multi-view sID is "narrow" again

The original design intent of NLT=4 multi-view tokenizer is to express one video through multiple complementary aspects, broadening sID semantics so retrieval can hit the video via any of several view-typed routes. P3 enables training all slots; this fix ensures the trained model actually expresses that diversity at inference time.

why per-slot codebook partitioning was rejected An earlier draft of F2 proposed splitting the shared 4096 codebook into 4×1024 disjoint slices. This was abandoned after recognizing two problems: (1) capability loss — each slot is restricted to 1024 centroids instead of the full 4096, reducing per-view representational capacity; (2) artificial separation — two videos with semantically similar views (e.g. both "action") would be forced to argmin to different codebooks just because they came through different slots, producing different sIDs for genuinely identical view content. The correct behavior is: same view content → same code, regardless of which slot produced it. View diversity should come from what the slots compute, not from which codebook range they argmin in.

2 Motivation

The right way to make 4 slots learn 4 distinct views is to put differentiation pressure on the training signal, not on the codebook structure. Three complementary mechanisms, each addressing a different failure mode of "P3 alone":

mechanismwhat it doesfailure mode it prevents
(a) soft-weighted CE via token_idx Slot[token_idx] gets weight 0.7 in CE; other slots get 0.1 / (N−1). All slots still receive gradient (no dormancy), but the slot routed by per-row caption k-means receives stronger pressure. Prevents the "4 MLPs converge to same function" collapse: different caption styles route to different slots' high-weight position → each slot specializes in a caption-style cluster.
(b) inter-slot orthogonality regularizer Add loss term λ·mean(|cos(slot_i, slot_j)|) for i≠j, pushing the 4 MLP outputs apart in feature space. Directly penalizes representational redundancy across slots. Even if (a)'s soft routing is weak, (b) provides an explicit "be different" gradient.
(c) per-slot k-means init at step 0 At codebook initialization, run N independent k-means on the per-slot encoder outputs (1024 centroids each), then concatenate into the shared 4096-codebook. After init, the codebook is shared and trained normally. Breaks the joint-NLT-flattened k-means init that produces ~300 dead codes on the diagnostic s3407 run (issue I2). Without (c), step 0 already starts with degenerate centroids that the optimizer cannot recover from.
design principle View diversity is a property of the trained representations, not a property of the codebook layout. If two videos genuinely have the same "action" view, the model should be able to send both to the same centroid — that is correct semantic aggregation. What we want to prevent is "the same video's 4 slots all map to the same centroid". Mechanisms (a)+(b)+(c) target the second case without breaking the first.
why all three, not just one (a) alone: relies on token_idx routing quality — if the per-video text k-means is noisy, the routing is noisy. (b) alone: provides differentiation pressure but no semantic anchor — slots will be orthogonal but it's unclear what "view" each represents. (c) alone: only fixes init; doesn't prevent training-time collapse. Together they cover routing signal + differentiation gradient + good initialization. Each is < 30 LOC; the bundle fits in one cell.

4.1 Mechanism (a) — soft-weighted CE via token_idx

P3's default (sum-of-N CEs / N) is the "uniform soft routing" baseline — every slot gets weight 1/N. Mechanism (a) replaces uniform weighting with a peaked distribution: slot[token_idx] gets high_w (default 0.7), every other slot gets low_w / (N-1) (default 0.1). All slots still receive gradient (so no dormancy), but the per-row caption-routed slot is the dominant supervisor.

# trainer/trainer.py — train_step (P3 + mechanism (a) soft-weighted CE)
multiview_all_slot_ce = bool(loss_weights.get('multiview_all_slot_ce', False))
view_div_high_w = loss_weights.get('view_div_high_weight', 0.7)   # default; sweep in S
view_div_low_w  = loss_weights.get('view_div_low_weight',  0.1)

if multiview_all_slot_ce:
    codes_per_slot = vid_outputs.discrete_codes              # [B, N]
    N = codes_per_slot.size(1)
    query_prob = query_outputs.probability                    # [B, code_number]
    token_idx = batch['token_idx']                          # [B]

    # Build per-row slot weights: peak at token_idx, low elsewhere
    slot_weights = torch.full((codes_per_slot.size(0), N),
                              view_div_low_w / max(N - 1, 1),
                              device=codes_per_slot.device)
    slot_weights.scatter_(1, token_idx.unsqueeze(1), view_div_high_w)
    slot_weights = slot_weights / slot_weights.sum(dim=1, keepdim=True)
                                                              # [B, N]; rows sum to 1

    ce_loss = 0.0
    for t in range(N):
        per_row = F.cross_entropy(
            query_prob,                                       # [B, code_number]
            codes_per_slot[:, t].detach(),
            label_smoothing=0.1,
            reduction='none',
        )                                                     # [B]
        ce_loss = ce_loss + (per_row * slot_weights[:, t]).mean()

4.2 Mechanism (b) — inter-slot orthogonality regularizer

Compute the cosine similarity matrix among the N slot features per row, take the absolute value of off-diagonal entries, and average. Add to the total loss with weight w_ortho (sweep in S screening over {0.01, 0.1, 1.0}).

# trainer/trainer.py — same train_step, after CE / code_loss / cl_dd_loss / rq_loss
w_ortho = loss_weights.get('slot_orthogonality_weight', 0.0)
if multiview_all_slot_ce and w_ortho > 0:
    # vid_outputs.continuous_embeds is [B, N, D]
    slot_feats = F.normalize(vid_outputs.continuous_embeds, dim=-1, eps=1e-12)
    sim = slot_feats @ slot_feats.transpose(-1, -2)           # [B, N, N]
    eye = torch.eye(N, device=sim.device).unsqueeze(0)        # [1, N, N]
    off_diag = (sim - eye).abs()                              # diagonal nulls out; off-diag = |cos|
    ortho_loss = off_diag.sum(dim=(-1, -2)) / (N * (N - 1))    # mean per batch row
    total_loss = total_loss + w_ortho * ortho_loss.mean()

Notes:

  • Operates on the continuous encoder output, not the quantized output — we want the MLP outputs to be different even before VQ snaps them to centroids.
  • (sim - eye) zeroes out the diagonal (slot-to-itself cosine = 1 trivially). .abs() penalizes both positive and negative correlation; orthogonal slots get loss = 0.
  • Cost: one batch-matmul over [B, N, D] tensors — negligible.

4.3 Mechanism (c) — per-slot k-means init at step 0

Modify VectorQuantizer.init_emb so that when per_slot_init=True AND the data shape implies N>1 slots, run N independent k-means each on B samples and n_e/N centroids, then concatenate into the shared nn.Embedding(n_e, D). The codebook stays shared; only the init seeds are slot-aware. After init, every slot's argmin can land anywhere in the n_e codebook.

# models/video_rqvae/vq.py — VectorQuantizer.init_emb
def init_emb(self, data):
    """Initialize codebook with k-means. If per_slot_init=True and the
    flattened input came from a multi-slot encoder (B*N, D), run N k-means
    on the per-slot batches and concatenate. Otherwise: standard single k-means."""
    if getattr(self, 'per_slot_init', False) and self.num_latent_tokens > 1:
        BN, D = data.shape
        N = self.num_latent_tokens
        assert BN % N == 0, f"data {BN} not divisible by num_latent_tokens {N}"
        assert self.n_e % N == 0, \
            f"n_e={self.n_e} not divisible by num_latent_tokens={N} for per-slot init"
        B = BN // N
        slot_k = self.n_e // N                                # 1024 when n_e=4096, N=4

        # [B*N, D] -> [B, N, D] -> [N, B, D]; each slot gets B samples
        data_per_slot = data.view(B, N, D).permute(1, 0, 2)

        per_slot_centers = []
        for t in range(N):
            centers_t = kmeans(data_per_slot[t], slot_k, self.kmeans_iters)
            per_slot_centers.append(centers_t)                # [slot_k, D]

        centers = torch.cat(per_slot_centers, dim=0)          # [n_e, D]
    else:
        # Standard single k-means on all B*N samples (current behavior)
        centers = kmeans(data, self.n_e, self.kmeans_iters)

    self.embedding.weight.data.copy_(centers)
    self.initted = True
key invariant The codebook nn.Embedding(n_e, D) is one shared parameter. Mechanism (c) only changes how the initial n_e centroids are computed: instead of one k-means on B×N points, it's N k-means on B points each, with the resulting centroids concatenated row-wise. After init, the forward path is unchanged — every slot argmins against the full vocabulary. Two videos' "action" view from different slots can argmin to the same centroid (correct semantic aggregation).

4.6 Diagnostic measurements for view diversification

In addition to CanHit@100, evaluate the trained model's actual view diversity. Add to the eval-time logging:

diagnosticwhat it measureshealthy value
per-slot unique-code countNumber of distinct codes each slot produces over the test poolEach of 4 slots: > 500 unique codes (out of 4096 vocab)
inter-slot mean cosineMean <cos(slot_i, slot_j)> over i≠j on test set continuous embeds< 0.5 (slots are measurably different in feature space)
cross-slot code overlapHow often slot_i's code = slot_j's code for the same video< 30 % (some overlap OK when views genuinely match; full collapse is > 90 %)
per-video sID multiplicityHow many distinct codes a single video produces across its N slots> 2 on average (the "broader sID semantic" goal)

These diagnostics distinguish "F2 won because the slots truly diversified" from "F2 won by coincidence and the slots are still collapsed". Both outcomes pass H2 on CanHit@100, but only the first satisfies the original design intent.

success criterion for this fix F2 passes the primary gate when (i) CanHit@100 > B1 single-seed full chain on 500K, AND (ii) the four view-diversification diagnostics above are in their healthy ranges. If (i) passes but (ii) shows view collapse, the win is suspicious — report it explicitly in results.html as "won despite collapsed views" and treat it as a follow-up question.
