Fix design — P3

P3 — All-Slot CE Supervision (the foundation fix)

Removes the select(token_idx) reduction in the train_step so all N slots of the multi-view encoder receive retrieval-aware CE/code gradient on every row. This is the only fix that directly addresses the foundation cause identified in diagnostic §2.5. P3 is the backbone of cell F2 (P3 + view diversification); it is never run standalone (an earlier "F1 = P3 alone" cell was dropped because, without view-diversification constraints, the 4 MLPs predictably collapse to the same function — confirming this prediction is not worth ~15 h H100 wall).

1 Challenge

code anchors: models/grdr.py:203-214 · trainer/trainer.py:154,184 · models/video_rqvae/encoder.py:354-376

The multi-view encoder produces [B, N, D] — one MLP output per slot. The train_step then reduces this back to [B, D] by picking one slot per row using token_idx, and runs the cross-entropy loss only on that selected slot. The other N−1 slots receive no retrieval-aware gradient on this row; their parameters drift only through the slot-permutation-invariant reconstruction and rq losses.

  CURRENT (broken):  multi-view in the encoder, single-route in the loss
  ─────────────────────────────────────────────────────────────────────
   video features ─► encoder ─► [slot0, slot1, slot2, slot3]   (shape [B, 4, D])
                                  │      │      │      │
                              select(token_idx[i])  ←─ picks ONE slot per row
                                  │
                                  ▼
                              [B, D]    ←─ N-1 slots DROPPED from CE loss
                                  │
                                  ▼
                         CE(query_prob, selected_code)   ← supervises 1 of 4

Combined with multi-caption-per-video (pseudo on Panda; native on MSR-VTT), token_idx varies per row of the same video, so different captions of one video supervise different slots with potentially different code targets. The codebook never anchors; the encoder MLPs drift on slot-permutation-invariant reconstruction signal; at the loop-0→loop-1 boundary the layer-0 indices flip for 25 % of samples; CanHit@100 craters from 88.06 (loop-0 fit) to 41.13 (loop-1 main).

measured impact (diagnostic s3407 run) NLT=4 + pseudo with current single-slot CE: CanHit@100 = 44.59 (model-3-fit) vs NLT=1 anchor 95.57 — a −50.98 pp gap at matched compact budget. The full per-loop trajectory and 4-mechanism breakdown are at diagnostic §1.

2 Motivation

The foundation cause is mechanically certain (see diagnostic §2.5 E calibration row, HIGH confidence): per-video num_texts > 1 ∧ NLT > 1 ∧ select-one-slot CE. P1 (shared token_idx) addresses the middle conjunct only — it removes per-row token_idx variance but leaves the slot-selection reduction in place, which means the configuration degenerates to "NLT=1 + 3 dormant MLPs" (row 3 of the 2×2 truth table). P2 (per-slot k-means init) addresses dead-code seeding only.

P3 is the only fix that targets the foundation conjunct directly: it removes select-one-slot CE from the equation. After P3, every row supervises every slot with that row's caption mapped to that slot's own code. The "multi-view" property of the encoder — which is structurally present at every forward pass — becomes a property of the trained model too. None of the other §5 probes can deliver this.

design choice — cross-loss vs marginalized CE Two ways to "supervise all slots". Option A (sum of N CEs): compute N separate CE losses, one per slot, against each slot's own code target. Each slot learns "what code would the encoder pick for this video, in this slot". Option B (marginalized CE): aggregate the N slot codes into a single softmax via logsumexp and CE against that distribution. A is simpler to reason about and easier to ablate per-slot weights; B is a tighter analogue of MaxSim eval. This package defaults to A. If A wins (F2 cell), B becomes a follow-up package; if A fails, B is a contingency.

4.1 models/grdr.py::_forward_video — add an all_slots return path

Current behavior reduces [B, N, D] to [B, D] via select(token_idx). Add a branch that returns the full N-slot tensor when multiview_all_slot_ce=True is propagated from the trainer.

# models/grdr.py — _forward_video (the broken-vs-fixed branch)
def _forward_video(self, video_features, token_idx, ..., return_all_slots=False):
    video_encoded_features = self.video_rqvae.encoder(video_features)         # [B, N, D]
    video_quantized_features, rq_loss, indices, distances, residuals = \
        self.video_rqvae.rq(video_encoded_features, ...)                       # indices [B, N]

    B = video_encoded_features.size(0)
    batch_indices = torch.arange(B, device=video_encoded_features.device)

    if return_all_slots:                                # ─── NEW PATH (P3) ───
        # Skip slot reduction entirely. Return ALL N slots.
        all_code_logits = []                                # list of [B, N, C] per layer
        for layer_distances in distances:           # L residual layers
            layer_logits = (1 - layer_distances / 2) * self.logit_scale.exp().clamp(20, 100)
            all_code_logits.append(layer_logits)            # [B, N, code_number]
        code_logits = torch.stack(all_code_logits, dim=2)   # [B, N, L, code_number]

        return VideoOutput(
            continuous_embeds  = video_encoded_features,    # [B, N, D]   ← full
            quantized_embeds   = video_quantized_features,  # [B, N, D]   ← full
            discrete_codes     = indices[:, :, -1],         # [B, N]      ← last layer's code per slot
            probability        = code_logits[:, :, -1, :],  # [B, N, code_number]  ← all slots
            code_logits        = code_logits[:, :, :-1, :], # [B, N, L-1, code_number] for prior layers
            reconstructed_features = self.video_rqvae.decoder(video_quantized_features)[1],
            rq_loss            = rq_loss,
        )

    # ─── OLD PATH (preserved for NLT=1 / B1, B2 baselines) ───
    selected_encoded_features  = video_encoded_features[batch_indices, token_idx]
    selected_quantized_features = video_quantized_features[batch_indices, token_idx]
    selected_indices           = indices[batch_indices, token_idx]
    ...                                                       # unchanged
    return VideoOutput(continuous_embeds=selected_encoded_features, ...)

4.2 trainer/trainer.py::train_step — sum N CE + N code_loss when flag is on

# trainer/trainer.py — train_step (CE + code_loss broken-vs-fixed branch)
def train_step(self, model, batch, loss_weights, ...):
    ...
    multiview_all_slot_ce = bool(loss_weights.get('multiview_all_slot_ce', False))

    vid_outputs = model(
        video_features=batch['video_features'],
        token_idx=batch['token_idx'],
        return_all_slots=multiview_all_slot_ce,             # ← NEW kwarg propagated
    )
    query_outputs = model(input_ids=batch['input_ids'], ...)

    if multiview_all_slot_ce:                                # ─── NEW BRANCH (P3) ───
        # vid_outputs.discrete_codes is [B, N] — one code per slot
        # vid_outputs.probability     is [B, N, code_number]
        codes_per_slot = vid_outputs.discrete_codes         # [B, N]
        N = codes_per_slot.size(1)
        query_prob = query_outputs.probability               # [B, code_number] from T5

        # Sum N CE losses: query head predicts each slot's code per row
        ce_loss = 0.0
        for t in range(N):
            target_slot_code = codes_per_slot[:, t]          # [B]
            ce_loss = ce_loss + F.cross_entropy(
                query_prob,                                   # [B, code_number]
                target_slot_code.detach(),
                label_smoothing=0.1,
            )
        ce_loss = ce_loss / N                                 # average to keep loss-scale stable

        # Code loss: now also a sum over slots and layers
        if vid_outputs.code_logits is not None:
            # vid_outputs.code_logits: [B, N, L-1, code_number]
            # query_outputs.code_logits:               [B, L-1, code_number]
            # prior_codes (from batch['ids'][:, 1:1+n_pred]): [B, L-1]
            prior_codes = batch['ids'][:, 1:1+query_outputs.code_logits.size(1)]
            code_loss = 0.0
            for t in range(N):
                vid_code_loss_t = F.cross_entropy(
                    vid_outputs.code_logits[:, t].reshape(-1, code_number),
                    prior_codes.reshape(-1),
                )
                code_loss = code_loss + vid_code_loss_t
            code_loss = code_loss / N
            # query-side code loss stays single (the T5 head is per-row, not per-slot)
            query_code_loss = F.cross_entropy(
                query_outputs.code_logits.view(-1, code_number),
                prior_codes.reshape(-1),
            )
            code_loss = code_loss + query_code_loss
    else:                                                  # ─── OLD BRANCH (B1, B2, B3 baselines) ───
        ce_loss = F.cross_entropy(query_outputs.probability,
                                  vid_outputs.discrete_codes.detach(),
                                  label_smoothing=0.1)
        ...                                                   # unchanged code_loss path

    # Reconstruction loss (cl_dd_loss) and rq_loss remain unchanged —
    # they already operate on the full [B, N, D] quantized tensor.
    ...
    total_loss = w_ce*ce_loss + w_code*code_loss + w_recon*cl_dd_loss + w_rq*rq_loss
    return total_loss
implementation note — backward graph cost The all-slot branch does N forward + N backward through the cross-entropy on the query head. T5 forward + encoder forward are not re-run — they happen once and the result is broadcast. The extra cost is N small F.cross_entropy calls + the vid_outputs.code_logits retaining a larger tensor through the backward pass. Empirically expect < 1.5× step time vs single-slot CE (the dominant cost is still T5 forward + RQ k-means). The diagnostic doc's compute table estimated 3× — that was a conservative upper bound; we will validate at smoke-test time and update if wrong.
