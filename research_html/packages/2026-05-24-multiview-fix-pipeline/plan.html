Run conventions (global rules, package-wide)

Binding on every experiment in this package (P0, B1, B2, B3, F2, F3, S, V) and any follow-up cell added later:

  1. R-LOG: wandb required. Every training and evaluation run must log key metrics to wandb (loss curves, CE/RQ/recon losses, codebook-usage diagnostics, eval CanHit@K, avg_candidates_per_query, throughput). No silent file-only runs. Launcher scripts must pass --use_wandb (or equivalent project flag) and set --wandb_project / --wandb_run_name to 2026-05-24-multiview-fix-pipeline / <cell-id>_s<seed>. A run that crashes before its first wandb step counts as a failed launch and must be re-launched, not patched post-hoc.
  2. R-BUNYA-24H: interactive 24h allocation for on-node debugging. Every Bunya cell (compute: "bunya" in inventory — currently F2, V; plus any future Bunya cell) must run inside an interactive salloc allocation of --time=24:00:00 (gpu_sxm partition, qos=sxm). No sbatch for these cells during the workstation→Bunya transfer window. Rationale: the multi-view pipeline edits (all-slot CE, view-diversification bundle) are first-time-on-Bunya code paths; live shell access on the compute node is required for fast iteration on shape/dtype/oom issues without burning a fresh queue wait per fix. Parallel cells share a single 2-GPU allocation via CUDA_VISIBLE_DEVICES=0/1 when SXM availability allows (see MEMORY: Bunya H100 SXM interactive pattern, Pre-allocate Bunya GPU before need).

enforcement: launcher scripts under scripts/ must hard-code both rules (no opt-out flag). Tracker launch-readiness (T21) ack must confirm both rules satisfied before any cell flips to EXPERIMENT_RUNNING. A cell that ran without wandb or on a non-interactive Bunya batch job is not a valid result-gate witness — re-run is required before the row can be inserted into results.html.
